# Bug audit — 2026-10-07

Code review of the whole repo (back domain, back services/IPC, front hooks/lib,
front components) at commit `e3e0421` plus the uncommitted working tree. At audit
time `pnpm typecheck` was clean and `pnpm test` was green (331 back / 194 front);
none of the bugs below were covered by the existing suite.

This document is the work list for whoever fixes them. Each bug has an ID, the
location, a reproduction, the expected behaviour, and the regression test that
reproduces it.

## How the regression tests work

Every reproducible bug has a test that asserts the **correct** behaviour and is
marked as an expected failure, so the suite stays green until it is fixed:

| Where                                                   | Marker        | Run                                                                                  |
| ------------------------------------------------------- | ------------- | ------------------------------------------------------------------------------------ |
| `apps/back/test/known-bugs/domain.known-bugs.spec.ts`   | `it.fails`    | `pnpm --filter @rdlc-designer/back exec vitest run test/known-bugs`                  |
| `apps/back/test/known-bugs/services.known-bugs.spec.ts` | `it.fails`    | same                                                                                 |
| `apps/front/src/lib/known-bugs.spec.ts`                 | `it.fails`    | `pnpm --filter @rdlc-designer/front exec vitest run src/lib/known-bugs.spec.ts`      |
| `apps/back/e2e/known-bugs.spec.ts`                      | `test.fail()` | `cd apps/back && pnpm build:e2e && pnpm exec playwright test e2e/known-bugs.spec.ts` |

E2E note: if the shell has `ELECTRON_RUN_AS_NODE=1` set (it was set in the audit
environment), Electron dies with "bad option: --remote-debugging-port=0" and every
e2e suite fails. Unset it first (`env -u ELECTRON_RUN_AS_NODE …` in bash,
`Remove-Item Env:ELECTRON_RUN_AS_NODE` in PowerShell). Each `describe` in the e2e
file launches its own app on a temp copy of a fixture.

At the time of writing, every marked test was run **without** its marker and
failed on its intended assertion (not on setup), and the suites were green with the
markers: back 364 tests, front 196, e2e known-bugs 11.

**Timing-sensitive tests:** BUG-22a (concurrent writes, 8 writers × 10 rounds) and
BUG-38 (colour commit within 250 ms) depend on a race. They reproduced on every run
during the audit, but if one ever "unexpectedly passes" while still marked, suspect
timing before assuming it's fixed.

Each `describe` is named after its bug ID (`BUG-NN …`). Fixing workflow:

1. Remove the `.fails` / `test.fail()` marker from that bug's test(s).
2. Run it: it fails, and the assertion message tells you what is still wrong.
3. Fix the production code until it passes. Do not weaken the assertion; if the
   expected behaviour in the test is genuinely wrong, change it and say why in
   the commit.
4. Run the full suite (`pnpm test`, plus `pnpm e2e` for UI bugs) and update the
   status of the bug in this document.

If a fix makes a still-marked test pass, Vitest/Playwright reports it as a
failure ("expected to fail"): that test's marker must be removed too.

Status legend: **open** · **fixed** · _doc-only_ (no automated test; reason given).

## Priority 1 — fix first

### BUG-01 · The `ports/` tree was never committed (fresh clones don't compile)

- **Where:** `apps/back/src/application/ports/**`, `.gitignore`.
- **What:** the old `out/` rule in `.gitignore` also matched `src/application/ports/out/`.
  `git ls-files apps/back/src/application` lists only `services/*`. Every
  committed revision, `HEAD` included, imports `../ports/out/*.js` that don't exist
  in git, so CI and any fresh clone fail to compile. The working tree already
  has the `.gitignore` negation (`!apps/back/src/application/ports/out/`) but
  the files are still untracked.
- **Fix:** `git add apps/back/src/application/ports .gitignore` and commit; verify
  with a clean clone (`git clone . /tmp/x && cd /tmp/x && pnpm i && pnpm typecheck`).
- **Test:** _doc-only_ (repository state).
- **Status:** fixed (el árbol `ports/` y la negación de `.gitignore` ya entraron en `eb9e205`; `git ls-files` los lista).

### BUG-02 · `deleteRows` / `deleteColumns` apply partially with no undo

- **Where:** `apps/back/src/domain/document/commands/tablixStructure.ts` → `deleteMany` (~705).
- **What:** the loop returns `left(...)` at the first rejected deletion without
  reverting the deletions already applied. No journal entry is pushed and the
  index is not rebuilt.
- **Repro:** select every row of a Tablix, delete. Rows go bottom-up until the last
  one is refused ("No se puede dejar el Tablix sin filas"); the others are gone and
  Ctrl+Z can't restore them. Same with a selection that hits a row starting a `RowSpan`.
- **Expected:** all-or-nothing, like `applyBatch` / `insertClones`: on failure the
  document is byte-identical to before.
- **Status:** fixed (`deleteMany` revierte los inversos ya aplicados con `applyCommand`).

### BUG-03 · Duplicating several items at once gives the copies the same `Name`

- **Where:** `commands/duplicateItem.ts:35` → `insertCloneAt` (`cloneInsert.ts:21`);
  front sends `batch` of `duplicateItem` (`apps/front/src/hooks/useItemEditing.ts:893`).
- **What:** each `duplicateItem` starts a fresh `taken` set and the index is only
  rebuilt after the batch, so each clone picks the same "next free" name (e.g. two
  `Textbox11`). Paste shares one set (`applyCommand.ts:210`); duplicate doesn't.
- **Expected:** all `Name`s unique (case-insensitive) after a multi-duplicate.
- **Found while testing:** the index is also not rebuilt between commands of a batch; fixing `duplicateItem` alone may not be enough unless the batch shares the `taken` set or refreshes the index.
- **Status:** fixed (`applyBatch` reconstruye el `DocumentIndex` entre comandos del lote).

### BUG-04 · Deleting the only row/column of a group breaks the hierarchy

- **Where:** `tablixStructure.ts` ~492 / ~664, `removeEmptyContainer` ~1151.
- **What:** when the deleted leaf was the only child, the empty `<TablixMembers>` is
  removed and the group's `TablixMember` (still with `<Group>`) becomes a leaf with
  no body row. The hierarchy has N leaves for N-1 rows → invalid in Report Builder,
  and every later leaf index is shifted by one.
- **Repro:** `addRowGroup` on row 2, then `deleteRow` 2.
- **Expected:** leaf member count == `TablixRow` count (and the same for columns);
  most likely the now-empty group member must go too.
- **Status:** fixed (`removeEmptyContainers` sube por la jerarquía quitando contenedores vacíos y grupos sin hoja).

### BUG-05 · `unmergeCells` / `addColumn` produce wrong cell counts under a `RowSpan`

- **Where:** `tablixStructure.ts` ~872 (`usesSlotCells`), ~556 (`addColumn`).
- **What:** `usesSlotCells` recognises the one-cell-per-column (SSRS/BC) layout only
  when the row has a `ColSpan`. Rows covered by a `RowSpan` have an empty filler
  `<TablixCell/>` per column but no `ColSpan`, so the "editor" branch runs and
  inserts an extra cell. `addColumn` in a row under a `RowSpan`×`ColSpan` block
  gets one filler too few.
- **Repro:** `ROWSPAN_XML` fixture: `addRow` at row 1, then `unmergeCells(0,0)` → the new
  row has 3 cells for 2 columns; Report Builder fails with "index out of range".
- **Expected:** every `TablixRow` stays consistent with the column count.
- **Found while testing:** root cause is `usesSlotCells` in `commands/tablixParts.ts` (it only detects the slot layout when a `ColSpan` overflows the count). The `addColumn` variant needs empty `<TablixCell/>` placeholders under the block; it does not reproduce with `ROWSPAN_XML`'s layout (covered cell omitted).
- **Status:** fixed (`rowSpanCoverage` + `usesSlotCells`/`positionedCells` con cobertura; `addColumn` crea el relleno y `unmergeCells` rellena el hueco).

### BUG-30 · A failed Open / New leaves the editor on a closed session

- **Where:** `apps/front/src/hooks/useDocumentCore.ts` `openPath` (~282-290), `createNew` (~312-317).
- **What:** the previous session is closed _before_ the new open/create succeeds; on
  failure only `setError` runs, so `doc` still holds the closed `sessionId`.
- **Repro:** with a report open, open a corrupt `.rdlc`. The old report stays on
  screen but every command/save/undo is rejected.
- **Expected:** close the old session only after the new one opened (or `setDoc(null)`
  on failure). The old document must stay fully usable.
- **Test detail:** stubs `dialog.showOpenDialog` to return a corrupt file; the alert shows "Sesión desconocida: <id>".
- **Status:** fixed (`openPath`/`createNew` abren/crean antes de cerrar la sesión anterior).

### BUG-31 · Rejected commands don't roll back the optimistic update

- **Where:** `useDocumentCore.ts:247-250`; `useItemEditing.ts` ~480, 511, 535, 562-584,
  630, 754, 775, 799, 967-983, 1025 (`reconcile(undefined)` on failure is a no-op);
  `setText`, `setParagraphs`, `setPageSize`, `setPageMargins`, `setReportCode` don't
  reconcile at all.
- **What:** the front patches the projection before the backend answers. The backend
  sends no snapshot on rejection (`CommandService.applyAndJournal` returns `left`
  before `touch`), so the canvas keeps showing a change the file doesn't have.
- **Expected:** on `!ok`, request a fresh projection (or revert the patch).
- **Test detail:** replaces the `rdlc:executeCommand` handler in main with one that always returns `E_COMMAND_REJECTED`, then nudges with ArrowRight.
- **Status:** fixed. Canal `rdlc:readProjection` (sesión → proyección vigente sin recargar del disco); `sendCommand` pide esa proyección y la adopta cuando el backend rechaza.

### BUG-32 · Report properties "Aplicar" grows short header/footer bands

- **Where:** `apps/front/src/components/panels/ReportPropertiesForm.tsx` 131-142 and
  `applyPage` ~190-207 (new, uncommitted file).
- **What:** heights start at `Math.max(height, DEFAULT_BAND_CM /* 1.25 */)` and
  `setRegionHeight` is sent for every present band on every apply.
- **Repro:** report with a 0.6 cm footer; change only a margin; Aplicar → footer 1.25 cm.
- **Expected:** existing bands keep their height; the 1.25 cm default only applies
  when a band is being inserted (`!initialPresent`). Ideally only send changed values.
- **Status:** fixed (el mínimo 1.25 cm solo al insertar; `setRegionHeight` se envía solo si el alto cambió respecto al último aplicado).

### BUG-33 · Tablix header strips misplaced when the Tablix has group headers

- **Where:** `apps/front/src/components/canvas/SelectionFrame.tsx` `TablixHeaders` (~286-470);
  `CanvasPreview.tsx` `computeSelectedFrame` (~577-597).
- **What:** column/row positions are counted from `rect.x/rect.y`, the measured
  `tablix-border`, which includes `tablixLayout().offset` (header bands). Body cells
  start at `offset` (`lib/tablix.ts:200-205`). The strips, resize zones and edge-drag
  preview line are shifted by the group-header width/height. `computeSelectedFrame`
  builds the Tablix box from body columns only, so the resize box is smaller than
  the drawn frame.
- **Expected:** header strips aligned with body columns/rows at any offset.
- **Found while testing:** `lib/tablix.ts` `tablixLayout` already handles `offset`; the bug is only in the components. The test covers the header strip, not `computeSelectedFrame`.
- **Status:** fixed (el offset viaja en `grid` — convertido a px de papel — y `TablixHeaders` lo suma a tiras, zonas de resize y previsualización).

## Priority 2 — saving and file safety

### BUG-20 · Save doesn't check the disk before writing

- **Where:** `apps/back/src/application/services/SessionService.ts` `save` (~139-154).
- **What:** conflict detection relies only on the watcher (`awaitWriteFinish` ≥ 80 ms,
  events dropped while `writing`, unreliable on network shares). Ctrl+S right after
  an external edit overwrites it with no conflict prompt.
- **Expected:** compare current mtime/size with the last known state before writing;
  return a conflict instead of overwriting. (No conflict error class exists yet; the
  test only requires a `Left` and that the external content is still on disk.)
- **Fix:** `save` comprueba el disco (`referenceStillOnDisk`: mtime/tamaño y, si
  difieren, el contenido) y devuelve `FileConflictError` (`E_CONFLICT`, clase nueva)
  sin escribir. Tras un conflicto detectado por el watcher la referencia pasa al
  estado externo, para que el «sobrescribir» explícito del usuario no se rechace dos
  veces por el mismo cambio.
- **Status:** fixed.

### BUG-21 · Watcher ignores replacement files with an older mtime

- **Where:** `SessionService.ts:326` (`stat.mtimeMs <= session.lastWriteMs`).
- **What:** Explorer copy-replace, robocopy and `git restore` can keep the source's older
  mtime; the change is treated as our own echo, and the next save overwrites the
  restored file.
- **Expected:** detect by `!==` mtime plus size (or a content hash).
- **Fix:** el eco exacto se filtra por mtime/tamaño iguales a la referencia; cuando el
  mtime **no avanza** decide el contenido (`bytes.equals(originalBytes)`), así un
  reemplazo con mtime anterior recarga o avisa en vez de ignorarse.
- **Status:** fixed.

### BUG-22 · Concurrent saves share one temp file; temp left behind on failure

- **Where:** `apps/back/src/infrastructure/fs/NodeFileSystemAdapter.ts:14-17`.
- **What:** temp name is `${path}.tmp-${pid}`. Two overlapping saves (double Ctrl+S,
  Save racing "save and close"; the front has no in-flight guard,
  `useDocumentCore.ts:326`) write the same temp; the second rename fails with
  `ENOENT` → false "error al guardar". A failed rename (`EPERM`/`EBUSY` from
  antivirus/locks) leaves a `.tmp-NNNN` next to the report.
- **Expected:** unique temp name per write, temp removed on failure; optionally
  serialise saves per session. On Windows some rejections are `EPERM`, not only `ENOENT`.
- **Fix:** temporal único por escritura (`<path>.tmp-<pid>-<uuid>`), borrado si la
  `rename` falla y escrituras al **mismo** destino serializadas por ruta (en Windows
  dos `rename` solapadas al mismo fichero fallan con EPERM aunque el temporal sea
  único). Reintentos cortos para EPERM/EACCES/EBUSY transitorios de antivirus/indexador.
- **Status:** fixed.

### BUG-23 · Session leaks when schema validation throws during open

- **Where:** `SessionService.ts:110-118`; `infrastructure/validation/LibXml2SchemaValidatorAdapter.ts:25`.
- **What:** the session is added to the map and the watcher started before
  `schema.validate()`. `validate` calls `XmlDocument.fromString` outside its `try`,
  so XML that xml-trueformat accepts but libxml2 rejects (undeclared entity,
  `encoding="utf-16"` on UTF-8 bytes) throws out of `open()`. The renderer gets
  `E_UNEXPECTED` without the `sessionId`; the session and watcher can't be closed.
  The same throw in `serializeValidated` makes Save fail with a generic error
  instead of `ValidationFailedError`.
- **Expected:** validation never throws (returns problems); nothing is registered
  until open fully succeeds.
- **Fix:** `validate` de libxml2 captura también el parseo (`XmlDocument.fromString`)
  y devuelve problemas; `open`/`reload` validan antes de registrar la sesión (un
  validador que lance da `Left` limpio) y `serializeValidated` mapea un validador
  que lance a `E_VALIDATION` en vez de propagar la excepción.
- **Status:** fixed.

### BUG-24 · Session stays registered if `fileWatcher.watch` rejects during open

- **Where:** `SessionService.ts` ~110-114.
- **Expected:** a failing open leaves no session behind.
- **Fix:** `open` arranca el watcher **antes** de añadir la sesión al mapa; si
  `watch` rechaza devuelve `IoError` y no queda sesión registrada.
- **Status:** fixed.

### BUG-50 · Renderer can make the backend write to any path

- **Where:** `apps/back/src/presentation/ipc/IpcController.ts` `createNew` / `saveAs` (~114-163);
  `SessionService.ts:132` (`createNew` overwrites without checking).
- **What:** paths come straight from the renderer; nothing ties them to a path the
  native dialog returned, and `event.senderFrame` isn't checked. Only exploitable
  if the renderer is compromised (navigation, sandbox, `contextIsolation`, CSP and
  `window.open` are configured correctly in `main.ts:27-69`).
- **Expected:** only accept paths previously returned by `pickSavePath`/`pickFile`
  for that window (or perform the dialog in main).
- **Fix:** `IpcController` guarda las rutas que autoriza el usuario (`pickFile`,
  `pickSavePath`, fichero de arranque del CLI) y las exige en `openFile`/`createNew`/
  `saveAs`; al abrir también valen los recientes (los sirve el backend, no el
  renderer). El drop real se registra desde el preload con
  `webUtils.getPathForFile` en un canal que no está en `window.api`. Las **escrituras**
  (`createNew`/`saveAs`) solo aceptan rutas del diálogo de guardado.
- **Test:** back `test/known-bugs/ipc.known-bugs.spec.ts` (5 tests, añadido al índice).
- **Status:** fixed.

## Priority 3 — medium

### BUG-10 · `setStyle` undo isn't byte-exact when the item had a previous value

- **Where:** `commands/setStyle.ts` ~99, ~121.
- **What:** inverse is `[…, setStyle(previous), ...restored, ...changes]`; undo runs it
  reversed, so paragraph/run overrides are restored first and then `setStyle(previous)`
  runs `syncShadowingStyles` again, overwriting them and re-creating run tags.
- **Repro:** run 8pt, textbox 10pt, set 12pt, undo → run ends at 10pt; doc stays dirty.
- **Expected:** byte-identical XML after undo.
- **Fix:** `applySetStyle` coloca `setStyle(previous)` **detrás** de `...restored` en
  la lista de inversos; al aplicar el undo al revés, el estilo del item (y su
  sincronización) vuelve **antes** que los overrides originales de párrafos/runs,
  que quedan byte a byte como estaban.
- **Status:** fixed.

### BUG-11 · Item and group names can collide

- **Where:** `commands/tablixGroups.ts` `nextGroupName` (~211/752); `DocumentIndex.has`;
  `setName`, `insertItem`, `duplicateItem`.
- **What:** `setGroupName` treats items and groups as one namespace, but
  `nextGroupName` only checks `Group`/`DataSet` (grouping on `=Fields!Description.Value`
  next to a textbox `Description` creates group `Description`), and item naming
  only checks the index (report items), so a textbox can be renamed to an existing
  group name.
- **Expected:** one case-insensitive namespace for items and groups.
- **Fix:** namespace compartido (sin distinguir caja) entre items y grupos:
  `nextGroupName` consulta también `ctx.index`; `setName`, `insertItem` y
  `duplicateItem` consultan los `<Group>` con `findGroupByName` (`scopeNames.ts`).
  En el test de `setName`, el textbox `D2` se renombra **antes** de crear el grupo
  para que `D2` quede libre (con el namespace unificado el grupo nacería `D21`);
  la aserción (rechazar el rename al nombre del grupo) no cambia.
- **Status:** fixed.

### BUG-12 · Clone/paste renames items but not references to them

- **Where:** `commands/cloneInsert.ts` `renameDescendants` (~44-53).
- **What:** `Group`, `ChartSeries`, `ChartArea`, `ChartLegend`… get new names but
  `ToggleItem`, `ReportItems!X`, scope strings (`Sum(…,"Group1")`) and chart
  `ChartAreaName`/`LegendName` still point at the originals → Report Builder errors.
- **Expected:** references inside the clone follow the rename.
- **Fix:** `insertCloneAt` construye el mapa old→new de todo el subárbol (raíz
  incluida) y `rewriteReferences` reescribe `ToggleItem` y `ReportItems!X` dentro
  del clon. Las cadenas de scope (`Sum(…,"Grupo")`) quedan fuera: distinguir un
  literal de un scope exige parsear la expresión.
- **Status:** fixed.

### BUG-35 · Align / Distribute mix coordinate spaces

- **Where:** `apps/front/src/components/panels/MultiSelectionPanel.tsx:85`, `lib/align.ts:25`,
  `hooks/useMarqueeSelection.ts:84-97`.
- **What:** the marquee selects a rectangle _and_ its children (`flattenItems`);
  `movableIds` only drops cell contents; boxes use each item's own `top/left`,
  relative to different parents. "Alinear a la izquierda" moves the children to
  the rectangle's absolute left _inside_ the rectangle. Possibly also: "Eliminar los
  N elementos" on a parent + children sends `deleteItem` for children after the
  parent is gone, and the all-or-nothing `batch` may reject the whole delete.
- **Expected:** drop descendants of selected containers before aligning/deleting (or
  convert to a common coordinate space).
- **Test detail:** the unit test assumes the fix lands in `lib/align.ts` (it has the nested `children`). If you fix it in `useItemEditing`/`MultiSelectionPanel` instead, move the test accordingly.
- **Fix:** `topLevelIds` (`lib/align.ts`) descarta los ids contenidos en otro item
  seleccionado y `alignBoxes` lo aplica; el panel de multiselección usa el mismo
  filtro para «Eliminar los N elementos» (el `batch` ya no se rechaza por hijos
  cuyo padre desaparece).
- **Status:** fixed.

### BUG-36 · Hard bounds on rectangle children mishandle existing overflow

- **Where:** `apps/front/src/lib/resize.ts:114-124`, `components/canvas/ItemView.tsx:488-490`,
  `CanvasPreview.tsx:563-572` (uncommitted change).
- **What:** children overflowing their rectangle are legal RDL. Resizing one with only
  the S handle hits the `overflowRight` branch and silently cuts its width; dragging
  snaps it back inside. While moving a child into another rectangle the dragged node
  stays stuck at its old parent's edge until drop.
- **Expected:** only clamp the dimension being changed; don't shrink existing overflow.
- **Fix:** el recorte por `bounds` de `computeResize` se aplica por eje
  (`movesHorizontal`/`movesVertical`): un tirador S/E solo toca su eje y no recorta
  un desbordamiento preexistente del otro.
- **Status:** fixed.

### BUG-38 · Colour picked just before a selection change lands on the new item

- **Where:** `apps/front/src/hooks/useDeferredColor.ts:26-41`; `FormatToolbar.tsx:306`,
  `PropertiesPanel.tsx:157,160` (not keyed by item id).
- **What:** `commitRef` is refreshed every render and the 250 ms timer only flushes on
  unmount.
- **Expected:** flush when the target changes, or capture the target id when scheduling.
- **Found while testing:** `lib/deferredColor.ts` is correct; the bug is `commitRef` in the hook plus `BackgroundField` having no `key` (`PropertiesPanel.tsx:157`).
- **Fix:** `useDeferredColor` captura el commit **al programar** (`scheduledCommitRef`):
  el color pendiente se entrega al item para el que se eligió aunque cambie la
  selección; además `BackgroundField`/`BorderField` llevan `key` por item.
- **Status:** fixed.

### BUG-39 · Toolbar Delete ignores multi-selection

- **Where:** `apps/front/src/hooks/useItemEditing.ts:906-910`; `App.tsx:201`.
- **What:** only the keyboard path batches multi-delete (`useEditorKeys.ts:231-237`);
  the toolbar deletes only the last-selected item, and `.then(() => setSelectedId(null))`
  runs even when the delete failed.
- **Expected:** toolbar deletes the whole selection; selection is kept on failure.
- **Found while testing:** the Delete key path is fine; only the toolbar button is affected. The "clears selection on failure" part isn't asserted.
- **Fix:** `deleteSelected` borra toda la selección en un `batch` (un solo undo) y
  solo limpia la selección si el comando fue bien; además omite los hijos de
  contenedores seleccionados (`topLevelIds`).
- **Status:** fixed.

### BUG-40 · Selected cell can point outside the grid

- **Where:** `useItemEditing.ts:347-353`; `ItemView.tsx:774-787`; `insertItem` ~865-875.
- **What:** only the Tablix's existence is checked, not row/col bounds. After deleting

- **Expected:** clamp or clear `selectedCell` when out of bounds.
- **Fix:** `selectedCell` se deriva solo si el ancla, el foco del rango y las
  celdas `extra` siguen dentro de la rejilla actual del Tablix (filas y columnas

- **Status:** fixed.

### BUG-41 · Arrow keys / Delete act on the canvas while another control has focus

- **Where:** `apps/front/src/hooks/useGlobalKeys.ts:53, 111, 125`.
- **What:** `isTextField` checks only INPUT/TEXTAREA/SELECT and `defaultPrevented` is

### BUG-25 · `rd:TypeName` read as attribute (SSRS `.rdl` field types lost)

### BUG-27 · Reload / external change skip the schema checks `open` does

### BUG-28 · Undo isn't atomic

`CommandService.ts:159-166`: if inverse k fails after 1..k-1 were applied, the entry is
pushed back but the doc stays half-reverted; no index rebuild, no snapshot.
**Reproduced** (not speculative): undoing a batch `[setLocation X, setName X→Y]` runs the
setName inverse first (renames back to X by node), then the setLocation inverse looks X up
in an index that isn't rebuilt between inverses and fails → name reverted, position not.
Root cause is the stale index between inverses, plus the missing all-or-nothing.

- **Fix:** `undo` refresca el índice **entre** inversos (el rename intermedio deja la
  búsqueda por nombre lista para el siguiente) y, si un inverso falla, deshace los ya
  aplicados (todo-o-nada) antes de devolver el paso al `undoStack`.
- **Status:** fixed.

### BUG-29 · Lifecycle gaps

- `IpcController.ts:86` `pendingOpen` never cleared → a renderer reload reopens the

- `ChokidarWatcherAdapter.ts:16`: no `'error'` listener.

- **Pendiente:** las sesiones siguen sin estar atadas a la ventana (recarga del
  renderer); no lo cubre el test.
- **Status:** fixed.
